v2.3 brings the safety and reliability work across the Rust agent, dashboard,
terminal deployment tools, and macOS/Windows desktop installers.

### Agent and dashboard

- Confirmed LAN changes with reconnection and automatic rollback.
- Charge-policy reconciliation, guarded USB transitions, and validated Wi-Fi
  updates with rollback after observed failures.
- Bounded subprocess execution, shared radio samples, buffered logging, and
  streaming CSV downloads.
- A shared polling implementation with stale-response protection and visible data-source
  freshness/errors.
- Clearer home/login, Signal and favicon artwork; matching UL and Active/Idle
  carrier indicators on desktop and mobile.

### Installation and deployment

- Device identity and firmware verification before deployment writes.
- Credentials transferred as data, validated startup scripts, and reliable PIN
  updates/removal.
- Verified offline bundles, storage checks, staged file activation, retained
  recovery snapshots, and key-only SSH verification.
- Compatibility fixes for legacy ADB transfers and background process startup.
- macOS Apple Silicon and Intel installers/app ZIPs, plus Windows x64 MSI,
  setup EXE and portable ZIP, built by GitHub Actions from this release tag.
  All standalone installers include the v2.3 installer changes and download
  checksum-verified agent/dashboard release assets; verified offline bundles
  can also be reused.

### Unlock requirements

Locked devices require the router admin password and a firmware-compatible
backup-key suffix. The backup key/suffix is available in the
[upstream unlock discussion, issue #8](https://github.com/jesther-ai/open-u60-pro/issues/8).
The v2.3 installer asks for the suffix; it is not embedded in the packages or
copied into this repository. Choose the dashboard password separately, with an
optional six-digit PIN. Run the installer dry run before proceeding with unlock
or deployment.

### Validation and limits

Rust, Python, frontend, API-contract, secret-audit and native-installer checks gate
publishing. The reviewed application changes passed a staged physical MU5250 HK
B04 deployment, controlled reboot, stock daemon sync, WAN, SSH, login and live
metrics checks; normal screen/touch operation was confirmed by the owner.
Both the [agent/dashboard release workflow](https://github.com/dklasens/MU5250-OpenUI/actions/runs/33942298205)
and the [desktop installer workflow](https://github.com/dklasens/MU5250-OpenUI/actions/runs/33942298189)
completed successfully, including Linux, macOS and Windows checks. All nine
payload downloads were verified against the final SHA-256 manifest. Mac app
versions, architectures and signatures, the Windows portable app architecture
and bundled ADB, and the published dashboard assets were also checked.

Dashboard/API traffic uses HTTP on the LAN. Physical USB/charger failure paths,
LAN/Wi-Fi mutations and every firmware variant have not all been exercised.
Read [docs/SAFETY.md](https://github.com/dklasens/MU5250-OpenUI/blob/v2.3/docs/SAFETY.md)
before installing. The v2.3 Mac apps are ad-hoc signed, not Apple-notarized.
Windows may require a compatible USB driver and the built-in OpenSSH Client.
CI builds and tests do not establish end-to-end physical deployment through
every native installer UI.

No device passwords, serials, private backups, firmware emulators or virtual
environments are included. Installer versions use the full SemVer `2.3.0`.

### Downloads

- `zte-agent`: aarch64 Linux musl agent.
- `dashboard-dist.tar.gz`: static dashboard bundle.
- `.dmg` / `.app.zip`: choose `aarch64` for Apple Silicon or `x64`/`x86_64` for Intel Macs.
- `.msi` / setup `.exe`: Windows x64 installers; `*-portable.zip` includes ADB.
- `sha256sums.txt`: finalized SHA-256 checksums for all nine payload downloads.

Download the matching files and verify them with `sha256sum -c sha256sums.txt`
(or `shasum -a 256 -c sha256sums.txt` on macOS).
